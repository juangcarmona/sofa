## Purpose

Supply issues, projects, pull requests, checks, reviews, workflow runs, commits, and delivery references.

## Goals

Remain the authoritative source for repository work and source-side lifecycle evidence.

## Responsibilities

Expose source identities, timestamps, revisions, links, and access failures. Accept writes only when a separately accepted product and human decision authorize them.

## Boundaries

GitHub evidence does not prove human approval, product acceptance, or production health by itself.
