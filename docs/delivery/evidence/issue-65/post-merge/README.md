## Acceptance limits

The canonical lifecycle label stayed `status:backlog` alongside `ready` and `waiting-review`, as in the first experiment. Receipts and reservation overlays carry execution evidence; the canonical status label remains inconsistent. No workflow or label policy was silently rewritten to conceal this finding.

The initial candidate's [explicitly dispatched full verification](https://github.com/juangcarmona/sofa/actions/runs/40521345343) passed. Its separate [PR-event verification](https://github.com/juangcarmona/sofa/actions/runs/40521347685) initially reported `action_required` ([first observation](initial-pr-ci.json)); a subsequent owner-triggered attempt 2 passed ([later observation](initial-pr-ci-attempt-2.json)). This operator did not approve or rerun that PR-event workflow. GitHub documents that PR events created with `GITHUB_TOKEN` require workflow approval; see [GitHub's trigger behavior](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow). Workflow approval and human acceptance of an implementation remain separate facts.

For the feedback head, publication saved the PR but reported that CI could not start. The separate [PR-event run](https://github.com/juangcarmona/sofa/actions/runs/40522876517) reported `action_required` ([observation](feedback-pr-ci.json)). The operator explicitly dispatched the existing verification workflow on the updated branch in [run 40522957843](https://github.com/juangcarmona/sofa/actions/runs/40522957843), which passed on `e17e05b5f58315b40b11cd186818a9cf2c8654bd`; the [run observation](feedback-ci.json) retains the completed result. Chromium installation delayed this run before the complete verification suite passed. This preserves the failed automatic-start observation rather than treating recovery as native success. Manual verification executes the full test suite; the workflow's PR-only branch/commit-convention step does not run for a manual dispatch.
